# How to add a Python package

This project has two possible setups. Adding a package differs slightly by path.

## Path A: Local (conda)

```bash
# 1. Activate the project env
conda activate <project-name>

# 2. Install
pip install <package>
# or
conda install <package>

# 3. Record in src/setup/environment.yml
# Edit the file; add under pip: or dependencies: as appropriate.
# Pin the version so the env is reproducible:
#   - <package>==1.2.3   (pip)
#   - <package>=1.2.3    (conda)

# 4. Commit environment.yml
```

## Path B: GPU cluster (container + venv)

```bash
# 1. Inside a cluster session, source the project venv
source src/env/venv/bin/activate

# 2. Install into the venv (NOT the container — the container is read-only)
pip install <package>

# 3. Record in src/setup/environment.yml pip section
# Pin the version:
#   - <package>==1.2.3

# 4. Commit environment.yml
```

## When a package is already in the container

The base container (NGC PyTorch) includes many packages pre-installed (torch, torchvision, numpy, etc.). Those are tracked in `src/setup/container-packages.txt`, which is auto-generated by `project-setup.sh cluster` on first run.

**Do not edit `container-packages.txt` by hand.** If the list is stale (e.g. a new container image was released), regenerate it:

```bash
bash src/setup/project-setup.sh --refresh-container-packages
```

This starts a temporary container session, runs `pip list --format=freeze`, and writes the result to `container-packages.txt`. Commit the regenerated file.

## Why two sources?

- `environment.yml` = packages your venv installs on top of the base environment. These are the project-specific deps.
- `container-packages.txt` = packages baked into the base container. You don't install these — you just declare that your code may depend on them.

An import is satisfied by either source, so torch does not need to be listed twice.

## Common gotchas

- **Import name vs package name.** `import sklearn` comes from `pip install scikit-learn`. The check normalizes, but if something fails, verify the actual package name with `pip show <name>`.
- **Transitive deps.** If you `import X` and X comes from the package Y, you need Y in the env — not X. Example: `import yaml` needs `pyyaml` in `environment.yml`.
- **Unused imports.** Imports that aren't needed clutter both your code and the env file. Clean them up.
